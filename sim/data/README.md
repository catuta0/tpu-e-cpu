# sim/data — SC-TPU init files and test vectors (tasks SW-01a, SW-02, SW-03: spec rev C)

**Current revision: spec rev C** (ADR-009, task SW-03; seeds selected on validation data
by the pre-registered protocol, `reports/sw/seed_selection_revC.md`): default RNG_MODE 2,
mode-2 seeds = the rev A per-lane seeds, modes 0/1 seeds = the rev B pair, PARAMS
version 0x03. Superseded files are kept unchanged in [`revB/`](revB/README.md) and
[`revA/`](revA/README.md) for traceability.

Generated by `code/python/sctpu/train.py` (model, SW-01a — **not retrained for rev B
or rev C**: both change only the hardware RNG seeds) and `code/python/sctpu/gen_hex.py`
(everything else). Regenerate with:

```
cd code/python
../../.venv/bin/python -m sctpu.train      # -> model_params.json (+ reports/sw/*.json); unchanged since SW-01a
../../.venv/bin/python -m sctpu.gen_hex    # rev C (default): all files below + soc_expected.json
../../.venv/bin/python -m sctpu.gen_hex --spec-rev B --out <dir>   # rev B files (identical data to revB/)
../../.venv/bin/python -m sctpu.gen_hex --spec-rev A --out <dir>   # rev A files (identical data to revA/)
```

Normative spec: `design/architecture/ARCHITECTURE.md` section 5 (5.2, 5.3, 5.5 are
[BIT-EXACT]) with the rev C seeds (ADR-009; spec text in
`management/handoffs/software-engineer/SW-03.md`). Expected values come from the Python
golden model `code/python/sctpu/model.py`; vectors are recomputed by the slow
literal reference model (`logs/sw/gen_hex.log`: 593 vectors x 33 fields — all 360
of `tpu_vectors_mode2.txt`, all corner and short files, 24 of each other 360-vector
file — and `soc_expected.json`: 0 mismatching fields — SIMULATION).

### Rev C seeds

| RNG_MODE | LFSR_X seed(s) | LFSR_W seed(s) |
|---|---|---|
| 0, 1 | S(0) = ace1 (as rev B) | S(32768) = f9de (as rev B) |
| 2 (lane i = 0..7) | (0xACE1 + 0x3C5A i) mod 2^16 = ace1 e93b 2595 61ef 9e49 daa3 16fd 5357 (as rev A) | (0x7A5C + 0x2B67 i) mod 2^16 = 7a5c a5c3 d12a fc91 27f8 535f 7ec6 aa2d (as rev A) |

S(n) = LFSR state n single steps after 0xACE1. PARAMS (rev C) = 0x0302_0810 for
RNG_MODE 2 (version 0x03). Consequence (checked, `logs/sw/revC_data_consistency.log`):
the data lines of every mode-2 file equal `revA/`, those of every mode-0/1 file equal
`revB/`; only the `#` header differs.

### Revision tag in the files

Every vector file and RNG trace file starts with the comment line **`# spec_rev C`**
(`revB/` files carry `# spec_rev B`; rev A files in `revA/` have no tag; readers treat
"no tag" as rev A). These files use `#` comments, so the tag uses `#`, not `//` (a `//`
line would break the `#`-peeking readers of section 2 and `tests/tpu/tb_sc_tpu.v`).

The `$readmemh` init files (`weights.hex`, `bias.hex`, `input.hex`, `corner/*.hex`) are
**byte-identical in rev A, B and C** (they contain no RNG data; sha256 below) and
carry **no** revision line (manager decision D2 of SW-03: 5.6 fixes their line counts).

| File | sha256 (rev A = rev B = rev C) |
|---|---|
| `weights.hex` | b743fe71eb3d379fa4d628ad1a8fad90c5c0855432f8e771080d32f4932c51c8 |
| `bias.hex` | 1d1e138fd2653fcff598d8af0cc0264c2b78c62eee5bff3e7a761632c1a1da83 |

All hex is lowercase, no `0x` prefix, fixed width.

## 1. Init files (5.6), `$readmemh` compatible, no header lines

| File | Lines | Width | Content |
|---|---|---|---|
| `weights.hex` | 512 | 8 hex digits | weight RAM word w = bytes 4w..4w+3, little-endian (byte 4w in bits [7:0]). Byte address of W[l][j][i] = base_l + (floor(i/8)*16 + j)*8 + (i mod 8), base_1 = 0, base_2 = 1024 (5.5). Layer-2 padding neurons 10..15: code 0x80. Unused bytes 1280..2047: 0x00. |
| `bias.hex` | 32 | 4 hex digits | BIAS[b][15:0], 16-bit two's complement, b = 16*(l-1)+j. Layer-2 padding lanes 10..15: 0. |
| `input.hex` | 16 | 8 hex digits | INPUT words of test image position 0 (load_digits row 1496, label 7), 4 codes per word little-endian (input 4w in bits [7:0]). |

`model_params.json`: the trained parameters (codes `w1_codes[j][i]` 16x64,
`w2_codes[j][i]` 10x16, `b1_int16`, `b2_int16`), `act_shift_s` (= 0), the
dataset split (`test_indices` = load_digits rows of the 360 test images, in vector
order; `test_labels`), seeds and hyper-parameters.

## 2. Vector files (one inference per line)

Comment lines start with `#` (skip them). Every other line is ONE vector made of
**43 space-separated hex fields**:

| Field # | Name | Width | Meaning |
|---|---|---|---|
| 0 | pset | 1+ hex | parameter set: 0 = `weights.hex` + `bias.hex`; n = 1..8 = `corner/pset<n>_weights.hex` + `corner/pset<n>_bias.hex` |
| 1 | K | 1 hex | effective LOG2_L (4..a); write it to CONFIG[3:0] |
| 2 | s | 1 hex | ACT_SHIFT, write to CONFIG[6:4] |
| 3 | mode | 1 hex | RNG_MODE the RTL must be synthesised/elaborated with |
| 4 | idx | hex | vector index: position in `test_indices` (pset 0) or input-pattern number (corner) |
| 5 | label | 1 hex | dataset label 0..9 (f = not applicable); informative only, NOT the expected RESULT |
| 6..21 | in[0..15] | 8 hex | INPUT words to write at 0x040 + 4w |
| 22..25 | hidden[0..3] | 8 hex | expected HIDDEN words at 0x0C0 + 4w |
| 26..41 | score[0..15] | 8 hex | expected SCORE words at 0x080 + 4j (two's complement, all 16 lanes incl. padding 10..15) |
| 42 | result | 1 hex | expected RESULT[3:0] |

Suggested testbench reading (iverilog / verilator), peeking at the first character:
```verilog
c = $fgetc(fd);
while (c != -1) begin                       // -1 = EOF
  if (c == "#" || c == "\n") begin
    if (c == "#") r = $fgets(line, fd);      // skip rest of the comment line
  end else begin
    r = $ungetc(c, fd);
    r = $fscanf(fd, "%h %h %h %h %h %h", pset, K, s, mode, idx, label);
    for (w = 0; w < 16; w = w + 1) r = $fscanf(fd, "%h", in_w[w]);
    for (w = 0; w < 4;  w = w + 1) r = $fscanf(fd, "%h", hid_w[w]);
    for (w = 0; w < 16; w = w + 1) r = $fscanf(fd, "%h", score_w[w]);
    r = $fscanf(fd, "%h\n", result);
    // ... apply the vector ...
  end
  c = $fgetc(fd);
end
```
(or pre-process with a script; the format is deliberately one line per vector.)
Each vector is an independent inference: write INPUT, CONFIG (and, if pset
changes, WEIGHT RAM and BIAS), then START; the LFSRs reload on START (5.3), so the
expected values do not depend on the order of the vectors.

| File | pset | K | s | mode | Vectors |
|---|---|---|---|---|---|
| `tpu_vectors_mode2.txt` (rev B/C default mode) | 0 | 8 | 0 | 2 | all 360 test images |
| `tpu_vectors_mode0.txt` | 0 | 8 | 0 | 0 | all 360 test images |
| `tpu_vectors_mode1.txt` | 0 | 8 | 0 | 1 | all 360 test images |
| `tpu_vectors_K4_mode1.txt` | 0 | 4 | 0 | 1 | test positions 0..15 |
| `tpu_vectors_K10_mode1.txt` | 0 | 10 | 0 | 1 | test positions 0..15 |
| `tpu_vectors_corner_mode{0,1,2}.txt` | 1..8 | 4 | 0, 3, 7 | 0/1/2 | 51 per mode |

Corner parameter sets (`corner/pset<n>_*.hex`, same formats as section 1;
random contents use numpy seed 2026):

| pset | Name | Purpose |
|---|---|---|
| 1 | all_zero_codes | weights, inputs = 0x00, biases 0: SNG bits always 0, XNOR always 1, acc1 = 64L, HIDDEN = 0xff |
| 2 | all_255_codes | weights, inputs = 0xff: bit is 0 only when r = 255 |
| 3 | bias_sat_pos | random weights, all biases +32767 (B maximal, hidden clipped at 127) |
| 4 | bias_sat_neg | random weights, all biases -32768 (hidden 0, large negative scores) |
| 5 | argmax_tie_all | all layer-2 weights code 0 and equal layer-2 biases: all 16 SCOREs equal, RESULT = 0 |
| 6 | argmax_tie_3_7_padding_max | layer-2 rows 3 and 7 identical, both biased up: SCORE[3] = SCORE[7], RESULT = 3, padding lanes 10..15 larger but ignored |
| 7 | random_full_range | random codes and biases over the full int16 range |
| 8 | small_negative_bias_floor | trained weights, biases -1..-16 and -7..-112: at K=4 B = floor(bias/8) differs from truncation |

Each corner pset is run with s = 0, 3, 7 and with its own input pattern(s) plus
test image 0 (last idx). CONFIG.LOG2_L clamping (raw 0..3 -> 4, 11..15 -> 10) is
not encoded in the files: a testbench can re-run any K=4 (K=10) vector with raw
values 0..3 (11..15) and must get identical outputs.

## 3. RNG traces (debug aid)

`tpu_rng_trace_mode{0,1,2}.txt` (rev C seeds; header line `# seeds ...` lists them):
first 64 stream cycles after START. The states were generated with the leap-forward
masks and re-checked with 8 literal single steps per cycle in gen_hex.py. Fields (hex):
cycle number, LFSR_X state(s) after the cycle (1 in modes 0/1, 8 in mode 2),
LFSR_W state(s), r_x for input lanes 0..7, r_w for lanes 0..7 (r of weight lane
(j,i) is shared by all neurons j). The state is the value AFTER the 8 single steps
of that cycle; r = its low byte (mode 1: rotl8(r, lane)). The seed itself is
never used as r (reading A2 of the SW-01a handoff).

## 4. SoC golden expectation — `soc_expected.json` (rev C)

Golden result of the default image `input.hex` (test position 0, load_digits row 1496,
label 7) with `weights.hex`/`bias.hex`, K = 8, s = 0 (CONFIG = 0x08, what
`soc_demo_prog.hex` writes), RNG_MODE 2, rev C seeds: `hidden_codes`/`hidden_words`
(HIDDEN at TPU 0x0C0), `score`/`score_words` (SCORE[0..15] at TPU 0x080, all 16 lanes),
`result` (RESULT), `expected_led`, `expected_uart_bytes`, `params_expected`
(0x03020810). Re-computed with the slow reference: `reference_crosscheck_mismatching_fields`
= 0. CYCLES is RTL-defined and not included. RESULT = 7 (= dataset label and = EV
model). The demo program itself (`soc_demo_prog.*`, SW-01b) does not depend on the
seeds: it was regenerated in SW-02 and is byte-identical. The rev B expectation is kept
in `revB/soc_expected.json`.

## 5. Labels

Expected values in these files are SIMULATION results of the Python golden model
(numpy 2.5.4, Python 3.13). They are not hardware measurements.

## 6. `revA/` — superseded rev A files (traceability only)

Byte-for-byte copies of the SW-01a files made before the rev B regeneration (see
[`revA/README.md`](revA/README.md)). Regenerating rev A with the current code
(`gen_hex --spec-rev A`) reproduces every data line of all 30 files (0 differences,
SW-02 handoff).

current code (`gen_hex --spec-rev B`) reproduces every data line of all 30 files
