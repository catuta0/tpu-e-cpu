## 1. What the system is

A small system-on-chip for the Sipeed Tang Nano 9K (Gowin GW1NR-LV9QN88PC6/I5, 8640 LUT4):

| Block | Summary |
|---|---|
| CPU | RV32I, multi-cycle FSM, no CSRs / interrupts; traps halt the core. Register file in 2 block RAMs. |
| RAM | 4 KiB at `0x0000_0000`, initialised with the demo program. |
| Peripherals | 6 LEDs, UART TX 115200 8N1, free-running cycle counter, TOHOST test mailbox (`0x1000_0000`). |
| SC-TPU | Stochastic-computing tensor unit (`0x2000_0000`): 16x8 weight-stationary tile of XNOR multipliers with accumulative parallel counters, 8-step leap-forward LFSRs, RNG mode 2 (independent per-lane generators). Runs a 64-16-10 MLP for 8x8 digits. Stream length L = 2^K, K = 4..10 (default 8). |
| Clock / reset | One 27 MHz clock (pin 52), no PLL; reset button on pin 3 (assumed to be S1) through a 2-FF synchroniser. |

There is **no firmware**. The only CPU program in the bitstream is the demo stimulus
`sim/data/soc_demo_prog.hex`, generated by `code/python/rv32/gen_soc_demo.py`. It configures the TPU
(K = 8, ACT_SHIFT = 0), starts one inference on the pre-loaded image, waits for DONE, writes RESULT to
the LEDs, sends `'0'+RESULT` and `'\n'` over the UART, stores CYCLES at RAM `0x0E00`, writes TOHOST = 1
and loops forever. For the pre-loaded image (test image 0, label 7) the expected result is class **7**:
LEDs on pins 10, 11 and 13 lit, UART text `7\n` (SIMULATION, `logs/soc/tb_soc_demo.log`).

Headline numbers (all SIMULATION; see the engineering report for labels and evidence):

| Quantity | Value |
|---|---|
| SC accuracy, mode 2, K = 8 (360 test images) | 94.4 % (340/360), 95 % CI 91.6–96.4 % |
| Expected-value / int8 reference | 95.0 % (342/360) |
| RTL vs golden model | 0 mismatching fields over 1454 inferences |
| SoC LUT4 / DFF / BSRAM | 5628 (65 %) / 2803 (43 %) / 5 of 26 |
| Worst-seed Fmax | 47.46 MHz (target ≥ 29.7 MHz) |
| TPU latency at K = 8 | 2928 cycles = 108.4 µs at 27 MHz |

## 4. Register map quick reference

### Memory map
| Base | Size | Slave |
|---|---|---|
| `0x0000_0000` | 4 KiB | RAM (program + data), reset PC = 0 |
| `0x1000_0000` | 0x20 | peripherals |
| `0x2000_0000` | 4 KiB | SC-TPU |
| other | — | reads 0, writes ignored, sticky `bus_err` (no hang) |

### Peripherals (`0x1000_0000`)
| Offset | Name | Access | Bits |
|---|---|---|---|
| 0x00 | LED | RW | [5:0], 1 = LED lit (pins active-low; inverted in the top) |
| 0x04 | UART_TX | W | [7:0] byte; ignored while busy |
| 0x08 | UART_STATUS | R | [0] tx_busy |
| 0x0C | CYCLE | R | 32-bit cycle counter since reset |
| 0x10 | TOHOST | RW | test mailbox: 1 = pass |

### SC-TPU (`0x2000_0000`)
| Offset | Name | Access | Bits / content |
|---|---|---|---|
| 0x000 | CTRL | W | [0] START (ignored while BUSY) |
| 0x004 | STATUS | R | [0] BUSY, [1] DONE |
| 0x008 | CONFIG | RW | [3:0] LOG2_L = K (reset 8, clamped 4..10), [6:4] ACT_SHIFT (reset 0) |
| 0x00C | RESULT | R | [3:0] class |
| 0x010 | CYCLES | R | busy cycles of the last inference (= 10·2^K + 368) |
| 0x014 | PARAMS | R | NL, IL, RNG_MODE, version: `0x0302_0810` in the release build |
| 0x040–0x07F | INPUT[0..63] | RW | one 8-bit code per byte, code = 128 + value·128 |
| 0x080–0x0BF | SCORE[0..15] | R | signed 32-bit per output lane |
| 0x0C0–0x0CF | HIDDEN[0..15] | R | one code per byte |
| 0x100–0x17F | BIAS[0..31] | RW | [15:0] signed (units 1/128), word 16·(layer−1) + neuron |
| 0x800–0xFFF | WEIGHT RAM | RW | 2 KiB, layout in ARCHITECTURE.md 5.5 |

Programming sequence for one inference: write the 16 INPUT words, write CONFIG, write CTRL = 1, poll
STATUS until bit 1 (DONE) is set, read RESULT (and CYCLES). Writes while BUSY are ignored; reads of the
buffers while BUSY may stall for up to ~35 cycles.

## 5. Programming the board yourself (NOT done in this project)

**This was not done in the project.** No board was connected, no bitstream was loaded and nothing on this
page has been tried on hardware. Loading a bitstream is your decision and at your own risk. The
pin assignment rests partly on an assumption: which of pins 3 / 4 is the button labelled S1 is not
confirmed by a source available to the project (the design uses pin 3 as reset; the other button is
unused). Both are push-buttons with pull-ups, so a swap only changes which button resets the design.

1. Rebuild and check the bitstream (row 9 of section 3.2). Its sha256 in the project run was
   `152d3c6dada6338e0b98a8fc19557ec95f4e40479e4f264411c72caa85b76258` (`logs/soc/pack.log`).
2. Install `openFPGALoader` on the host (it is not part of the project tool set).
3. Load into the FPGA's volatile configuration SRAM (lost at power-off; the board's flash is untouched):

   ```bash
   openFPGALoader -b tangnano9k sim/soc/build/soc_top.fs
   ```

   openFPGALoader can also write the external flash (option `-f`), which makes the design persistent
   across power cycles. The project gives no procedure for that and does not recommend it for a first
   test.
4. Open a serial terminal on the board's USB serial port at **115200 baud, 8N1, no flow control**, then
   press the reset button. Expected (from simulation): the terminal shows `7` followed by a newline;
   LEDs on pins 10, 11, 13 light up. The demo runs once per reset and then idles.
5. If you want to record the result as evidence, follow the physical validation plan in the engineering
   report (section "Physical validation plan"): it lists what to measure, with which equipment and
   against which requirement. Hardware results would be the project's first MEASUREMENTs.

## 6. Troubleshooting

| Symptom | Likely cause / action |
|---|---|
| `yowasp-yosys: command not found` | venv not activated: `source .venv/bin/activate`. The first call of a YoWASP tool compiles its WebAssembly and can take minutes. |
| P&R very slow or `Unable to find legal placement` | expected for dense variants (IL 16 at 73–77 % LUT4); the SoC at 65 % places in ~4–5 min per seed. Use `--threads 1` as the scripts do on a shared machine. |
| A simulation script stops at the `spec_rev guard` | vector/trace files in `sim/data` are not `# spec_rev C` (e.g. regenerated for another revision). Restore them from git or set `SPEC_REV` consistently. |
| A script dies with a syntax error at its last step | it was edited while running (bash reads scripts incrementally). Re-run it after the edit. |
| `sim_tpu.sh` takes very long | the three 360-vector files take ~7 min each in Icarus; `QUICK=1` skips them (not a full regression). |
| Log revision stamp ends in `-dirty` | the tree had uncommitted changes; commit and re-run if the log is to be evidence of a clean revision. |
| Numbers differ from the reports after re-running | check that weights were not re-trained (`retrained: false` in the JSON), that the spec revision matches, and the git revision in the log header. |
| LaTeX: `IEEEtran.cls not found` | install the TeX Live publishers collection (`texlive-publishers`). |
| openFPGALoader cannot open the cable | USB permissions (udev rules) or a charge-only cable; try another cable / port. |
| Board: no UART text | terminal opened after the demo ran (it runs once, ~0.2 ms after reset): open the terminal first, then press reset; wrong serial port if several appear; wrong baud rate. |
| Board: all LEDs off | bitstream not loaded, reset button held, or the button on pin 3 is not the one you think (see section 5). |
| Board: several `7` lines per press | button bounce (there is no debouncer; each bounce is a reset). Harmless. |
